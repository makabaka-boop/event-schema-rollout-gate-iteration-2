# 事件模式平台

三个协作模块：**模式注册**、**事件接入**、**消费者投影**。

## 模块

| 模块 | 文件 | 职责 |
|---|---|---|
| 模式注册 | `event_platform/registry.py` | 版本管理、管理员提案、发布/回退，发布前检查所有仍活跃消费者 |
| 事件接入 | `event_platform/ingestion.py` | 按声明版本验证事件、入库、隔离无效事件、触发投影；隔离事件更正重放 |
| 消费者投影 | `event_platform/consumers.py` | 消费者固定字段 ID 与类型、按各自视图生成投影 |
| 门面 | `event_platform/platform.py` | 三模块共享一把锁，跨模块操作原子完成 |

## 核心规则

- **字段身份 = 稳定数字 ID**；显示名称可重命名，不影响身份，投影以 ID 为键。
- 模式限定每个字段的**类型、是否必需、默认值**（`Field`）。
- 生产者按**声明的版本**提交事件，按该版本验证（不是当前可见版本）；
  发布新版本不弃用旧版本 —— 过渡期内新旧生产者都能提交有效事件，
  直到管理员显式 `deprecate`。
- 消费者注册/升级时固定 `{字段 ID: 类型}`，与当前可见版本核对。
- 发布/回退前检查所有仍活跃消费者：删除仍被需要的字段、
  类型不兼容变更一律拒绝；可见版本指针原子切换，失败不留中间状态。
- 无效事件进入隔离区；投影先为全部消费者构建完毕再与入库一次提交，
  不留部分投影。

## 隔离事件更正重放

生产者填错字段被隔离后，运营可经 `EventPlatform.replay_correction(...)`
提交更正，入参为四元组：**隔离记录标识、预期记录修订、声明的模式版本、
更正后的字段值**。

- 先按**声明版本**重新校验（不是当前可见版本）；随后对同一时刻快照出的
  **仍活跃消费者集合**检查字段映射能否满足，再构建全部投影。
- 全部步骤成功后，才在一次提交中发布正式事件、各消费者投影，并把隔离
  记录翻转为**已处理**（修订号 +1）；原失败负载与原因原样保留供审计。
- 校验失败、修订冲突、消费者映射无法满足或投影构建异常 -> 返回拒绝结果，
  不留下任何部分正式数据，记录修订也不推进。
- 四元组完全一致的重试返回首次的原结果（成功时含原回执）；不同内容的
  请求不能借用旧成功回执，已更正的记录拒绝任何新内容。
- 重放与模式发布/回退/弃用及消费者升级共用同一把锁与同一套跨模块原子
  裁决，校验版本与投影消费者视图不可能来自不同时刻。
- 旧生产者接入与未更正隔离记录的行为不变（隔离记录仍为 `pending`）。

## 运行测试

```bash
python3 -m unittest discover -s tests -v
```

`tests/test_event_platform.py` 中的 `InterleavedScenarioTest` 交错执行
发布新版 → 旧版写入 → 消费者升级 → 失败的发布/回退 → 成功回退，
逐步核对各方看到的版本与数据；`CorrectionReplayTest` 与
`ConcurrencyTest` 覆盖更正重放的版本切换、默认值、修订冲突、回执幂等
及部分投影失败（含并发交错）。
